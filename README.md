# Визуализатор графа зависимостей пакетов Rust (Cargo) — Вариант 22

## 1. Общее описание

Инструмент визуализации графа зависимостей для пакетного менеджера **Rust (Cargo)**.
Разработан в рамках Практической работы №2 по дисциплине
«Конфигурационное управление» (Вариант №22).

Инструмент извлекает данные о зависимостях пакетов Rust напрямую через
HTTP Sparse Index crates.io без вызова пакетных менеджеров и сторонних библиотек.
Построение графа зависимостей выполняется алгоритмом **поиска в ширину (BFS) с рекурсией**
с контролем максимальной глубины и обнаружением циклических ссылок.
Программа вычисляет топологический порядок загрузки/сборки и генерирует
текстовое представление графа зависимостей на **языке диаграмм D2**.

Проект включает реализацию всех 5 этапов:
1. **Этап 1:** CLI-приложение с чтением конфигурации формата TOML и валидацией.
2. **Этап 2:** Сбор данных о прямых зависимостях пакета заданной версии.
3. **Этап 3:** Рекурсивный BFS-обход, учет `max_depth`, обработка циклов и тестовый режим.
4. **Этап 4:** Определение топологического порядка сборки/загрузки зависимостей.
5. **Этап 5:** Визуализация графа на языке диаграмм D2.

## 2. Описание функций и настроек

### Параметры конфигурационного файла (`config.toml`):

| Параметр | Тип | Описание |
| :--- | :--- | :--- |
| `package_name` | `string` | Имя анализируемого пакета (например, `"serde"`) |
| `repo_url` | `string` | URL индекса crates.io (`https://index.crates.io`) или путь к тестовому файлу |
| `test_mode` | `boolean` | Режим работы с тестовым графом (`true` / `false`) |
| `package_version` | `string` | Версия пакета (например, `"1.0.195"`) |
| `max_depth` | `integer` | Максимальная глубина рекурсивного BFS-обхода ($\ge 0$) |

### Архитектура модулей:

* **`src.config`**:
  * `parse_toml(content)` — парсинг TOML без внешних зависимостей.
  * `validate_config(data)` — валидация типов, диапазонов значений и обязательных ключей.
  * `load_config(path)` — загрузка и валидация файла конфигурации.
* **`src.collector`**:
  * `get_crates_io_prefix(name)` — вычисление префикса Sparse Index crates.io (1, 2, 3 и 4+ символов).
  * `build_package_url(base, name)` — формирование URL к метаданным пакета.
  * `fetch_package_lines(url)` — загрузка строк JSON Lines по HTTP с корректным User-Agent.
  * `parse_version_deps(lines, version)` — извлечение списка normal-зависимостей для указанной версии.
  * `get_direct_dependencies(url, name, ver)` — получение прямых зависимостей пакета.
* **`src.graph`**:
  * `DependencyGraph` — класс ориентированного графа с фиксацией вершин, ребер и циклов.
  * `bfs_recursive(...)` — рекурсивный алгоритм BFS для поуровневого обхода графа.
  * `load_test_repository(path)` — загрузка тестового репозитория с именами из латинских букв.
  * `build_dependency_graph(...)` — сборка полного графа зависимостей.
* **`src.order`**:
  * `compute_loading_order(graph)` — топологическая сортировка пакетов по числу зависимостей.
* **`src.visualizer`**:
  * `render_d2(graph)` — формирование спецификации графа на языке диаграмм D2.
* **`src.main`**:
  * Консольный интерфейс с поддержкой выбора этапа (`--stage 1..5`).

## 3. Команды для сборки проекта и запуска тестов

Проект не требует сторонних зависимостей (работает на стандартном Python 3.9+).

### Запуск модульных тестов:
```bash
python3 -m unittest discover -s tests -p "test_*.py"
```

### Запуск демонстрационного скрипта всех этапов:
```bash
chmod +x run.sh
./run.sh
```

## 4. Примеры использования

### Запуск конкретного этапа:

```bash
# Этап 1: вывод параметров конфигурации
python3 -m src.main --config config.toml --stage 1

# Этап 2: вывод прямых зависимостей
python3 -m src.main --config config.toml --stage 2

# Этап 3: граф зависимостей и циклы (тестовый режим)
python3 -m src.main --config config.toml --stage 3

# Этап 4: порядок загрузки пакетов
python3 -m src.main --config config.toml --stage 4

# Этап 5: текстовое представление на языке D2
python3 -m src.main --config config.toml --stage 5
```

### Пример вывода D2 для пакета `serde` (v1.0.195):

```d2
direction: right
"serde".style.fill: "#87ceeb"
"serde".style.stroke: "#1e90ff"
"serde" -> "serde_derive"
"serde_derive" -> "proc-macro2"
"serde_derive" -> "quote"
"serde_derive" -> "syn"
```

### Демонстрация для 3 различных пакетов:

1. **`serde` (v1.0.195)**:
   * Зависимости: `serde_derive` $\to$ `proc-macro2`, `quote`, `syn`.
2. **`log` (v0.4.20)**:
   * Зависимости: базовые макросы и бэкенды логирования.
3. **`rand` (v0.8.5)**:
   * Зависимости: `rand_core`, `rand_chacha`, `libc`.

## 5. Сравнение с штатными инструментами Cargo (`cargo tree`)

При сравнении графа с выводом штатной утилиты `cargo tree` учитываются следующие особенности:

1. **Feature flags и опциональные зависимости**:
   * Штатный `cargo tree` по умолчанию включает зависимости,
     активированные текущими фичами по умолчанию (`default features`).
   * Наш анализатор извлекает канонические `normal` зависимости конкретного
     релиза из Sparse Index. Опциональные зависимости (`optional = true`)
     фильтруются, чтобы граф отражал обязательные зависимости библиотеки.
2. **Платформозависимые зависимости (`target/cfg`)**:
   * `cargo tree` на конкретной ОС (например, macOS) показывает только ветку
     для текущей платформы (например, `target.'cfg(unix)'.dependencies`).
   * Наш анализатор оперирует обобщенным графом зависимостей крейта.
3. **Dev- и Build-зависимости**:
   * `cargo tree --edges normal` отображает только обычные зависимости,
     что в точности согласуется с построенным графом.
