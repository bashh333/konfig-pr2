# Визуализатор графа зависимостей пакетов Rust (Cargo) — Вариант 22

## 1. Общее описание

Инструмент визуализации графа зависимостей для пакетного менеджера **Rust (Cargo)**.
Приложение разработано в рамках Практической работы №2 по дисциплине
«Конфигурационное управление» (Вариант №22).

Инструмент позволяет анализировать прямые и транзитивные зависимости пакета
заданной версии без использования сторонних пакетных менеджеров и специализированных
библиотек, строит граф зависимостей с помощью рекурсивного поиска в ширину (BFS)
с контролем максимальной глубины и циклических ссылок, определяет порядок
загрузки/сборки пакетов и формирует текстовое описание графа на языке диаграмм D2.

На **Этапе 1** реализован минимальный прототип с поддержкой конфигурационного
файла в формате **TOML**, валидацией всех параметров и демонстрацией обработки
ошибок.

## 2. Описание функций и настроек

Конфигурация приложения задается через файл формата TOML (по умолчанию `config.toml`).

### Настраиваемые параметры:

| Параметр | Тип | Описание |
| :--- | :--- | :--- |
| `package_name` | `string` | Имя анализируемого пакета (например, `"serde"`) |
| `repo_url` | `string` | URL-адрес репозитория/индекса или путь к тестовому файлу |
| `test_mode` | `boolean` | Режим работы с тестовым графом (`true` / `false`) |
| `package_version` | `string` | Версия анализируемого пакета (например, `"1.0.195"`) |
| `max_depth` | `integer` | Максимальная глубина анализа зависимостей ($\ge 0$) |

### Пример файла конфигурации (`config.toml`):

```toml
package_name = "serde"
repo_url = "https://index.crates.io"
test_mode = false
package_version = "1.0.195"
max_depth = 3
```

### Основные модули и функции (Этап 1):

* **`src.config`**:
  * `parse_toml(content: str)` — парсинг содержимого TOML (использует встроенный `tomllib` или легковесный парсер без внешних зависимостей).
  * `validate_config(raw_data: dict)` — проверка наличия всех параметров, их типов и допустимых диапазонов (например, `max_depth >= 0`).
  * `load_config(file_path: str)` — чтение, парсинг и валидация файла конфигурации с генерацией информативных исключений `ConfigError`.
* **`src.main`**:
  * `parse_args(args)` — обработка аргументов командной строки (`--config`, `-c`).
  * `print_config_parameters(config)` — вывод параметров в формате `ключ: значение` (требование Этапа 1).
  * `main(argv)` — точка входа в приложение, перехват и вывод ошибок конфигурации.

## 3. Команды для сборки проекта и запуска тестов

Проект не требует внешних зависимостей и работает на стандартном Python 3.9+.

### Запуск тестов:

```bash
python3 -m unittest discover -s tests -p "test_*.py"
```

### Запуск через скрипт `run.sh`:

Скрипт запускает автотесты и выполняет приложение с конфигурацией `config.toml`:

```bash
chmod +x run.sh
./run.sh
```

## 4. Примеры использования

### Стандартный запуск с конфигурацией по умолчанию:

```bash
python3 -m src.main --config config.toml
```

**Вывод:**
```text
package_name: serde
repo_url: https://index.crates.io
test_mode: False
package_version: 1.0.195
max_depth: 3
```

### Пример обработки ошибок:

1. **Если файл не существует:**
   ```bash
   python3 -m src.main --config non_existent.toml
   ```
   **Вывод в stderr (код возврата 1):**
   ```text
   Configuration error: Configuration file does not exist: non_existent.toml
   ```

2. **Если передан некорректный параметр (например, отрицательная глубина):**
   ```text
   Configuration error: Parameter 'max_depth' must be >= 0, got -1
   ```

3. **Если пропущено обязательное поле:**
   ```text
   Configuration error: Missing required parameter: 'package_name'
   ```
